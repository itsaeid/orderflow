# Seyfi Flow — سیفی فلو

سامانه فارسی مدیریت گردش سفارش گروه صنعتی سیفی.

## وضعیت تحویل

- رابط واقعی Next.js / TypeScript / Tailwind CSS و اجزای shadcn-style مبتنی بر Radix.
- پیش‌نمایش منتشرشده، **دموی خصوصی با localStorage** و انتخاب نقش آزمایشی است. انتخاب نقش احراز هویت نیست؛ اطلاعات محرمانه وارد نکنید.
- بک‌اند NestJS با احراز هویت، کنترل دسترسی سمت سرور و مخزن PostgreSQL در `server/` موجود است؛ **روی لینک دمو اجرا نمی‌شود**.
- تست API از NestJS واقعی، HTTP و PostgreSQL تعبیه‌شده PGlite استفاده می‌کند. تست استقرار روی سرور PostgreSQL مستقل انجام نشده است.

## اجرای محلی

Node.js 22 یا جدیدتر و PostgreSQL لازم است.

```bash
npm ci
npm test
npm run typecheck
npm run dev
```

بدون `NEXT_PUBLIC_API_URL` رابط در حالت دمو اجرا می‌شود. داده‌های نمونه با هشت نقش در دسترس‌اند و از صفحه تنظیمات قابل بازنشانی هستند.

## اجرای متصل به سرور

1. از `.env.example` یک `.env` بسازید؛ مقادیر نمونه را با رمزها و آدرس‌های واقعی جایگزین کنید.
2. PostgreSQL را فراهم کنید؛ فایل `compose.yaml` برای راه‌اندازی محلی دیتابیس موجود است. `POSTGRES_PASSWORD` باید در محیط تنظیم شود.
3. `DATABASE_URL`، `SESSION_SECRET` تصادفی حداقل ۳۲ کاراکتر و `WEB_ORIGIN` را تنظیم کنید.
4. برای ساخت اولین مدیرعامل، `BOOTSTRAP_EMAIL` و `BOOTSTRAP_PASSWORD` با حداقل ۱۲ کاراکتر تعیین کنید. این تنظیم فقط دیتابیس بدون کاربر را مقداردهی می‌کند.
5. API را اجرا کنید:

```bash
node --env-file=.env --import tsx server/main.ts
```

6. `NEXT_PUBLIC_API_URL=http://localhost:4000/api` را هنگام اجرای فرانت یا build تنظیم کنید. این متغیر در زمان build در خروجی Next.js قرار می‌گیرد.
7. برای محیط واقعی، فرانت و API را پشت HTTPS روی یک سایت/دامنه مستقر کنید؛ cookie از نوع HttpOnly و SameSite=Strict است و درخواست نوشتن فقط از WEB_ORIGIN پذیرفته می‌شود. `NODE_ENV=production` را برای cookie امن تنظیم کنید.
8. پس از ساخت حساب مدیر، متغیرهای bootstrap را از محیط حذف کنید.

### ساخت کاربران کارکنان و مشتری

متغیرهای `USER_EMAIL`، `USER_PASSWORD`، `USER_NAME`، `USER_ROLE` و برای مشتری `USER_CUSTOMER_ID` را تنظیم و اجرا کنید:

```bash
node --env-file=.env --import tsx server/create-user.ts
```

نقش‌ها: `ceo`, `sales`, `sales_manager`, `finance`, `production`, `qc`, `dispatch`, `customer`.
شناسه مشتری باید با `customerId` سفارش مطابقت داشته باشد. مدیریت کاربران در این نسخه از CLI انجام می‌شود؛ UI مدیریت کاربران پیاده‌سازی نشده است.

## ساختار

- `app/`: رابط فارسی، RTL، پنل مدیرعامل، کارتابل نقش‌ها و پنل مشتری.
- `components/ui/`: Button و Dialog مبتنی بر الگوی shadcn/Radix.
- `lib/workflow.ts`: ماشین حالت و قوانین قابل استفاده مشترک؛ مرجع نهایی مجوزها در API است.
- `lib/documents.ts`: سیاست دسترسی اسناد.
- `server/app.ts`: API NestJS، نشست، محافظ نقش و ورودی.
- `server/repository.ts`: تراکنش، قفل سطر، audit و outbox PostgreSQL.
- `tests/`: آزمون گردش کامل، برگشت، مجوز و API.

## گردش پیاده‌سازی‌شده

ثبت فروش → مدیر فروش → مالی اولیه → برنامه‌ریزی → تولید → QC → پیگیری تسویه → مالی و قرارداد → مدیرعامل → بارگیری → ارسال → تحویل.

برگشت با یادداشت اجباری؛ اصلاح نسخه سفارش در پیش‌نویس برگشتی؛ ثبت پرداخت فقط توسط مالی؛ الزام تکمیل تولید؛ گزارش QC و سریال؛ الزام تسویه و قرارداد قبل خروج؛ جداسازی ارسال و تحویل.

دوبار کلیک با requestId تکراری رویداد جدید ایجاد نمی‌کند. expectedVersion و قفل سطر مانع اعمال دو تغییر هم‌زمان روی نسخه قدیمی می‌شوند. تغییر مرحله، ثبت سابقه و outbox در یک تراکنش‌اند.

## اسناد

PDF، PNG و JPEG تا ۲ مگابایت؛ دانلود با کنترل دسترسی سرور. در دمو فایل در مرورگر و در API اولیه به صورت داده خصوصی در PostgreSQL ذخیره می‌شود. شماره نسخه فاکتور هنگام پیوست ثبت می‌شود. ارتقای فضای فایل به S3 برای حجم واقعی پیشنهاد می‌شود. مشاهده یا بارگذاری رسید به معنی تأیید وصول نیست.

## محدودیت‌های روشن نسخه اول

- هنوز استقرار API/PostgreSQL، دامنه شرکت، پشتیبان‌گیری و آزمون بازیابی عملیاتی انجام نشده‌اند.
- هر پرونده فعلاً یک نوع محصول با تعداد دارد؛ گردش و سریال مستقل برای تک‌تک دستگاه‌ها و ارسال جزئی پیاده نشده‌اند.
- پیشرفت تولید به‌صورت دستی توسط مدیر تولید ثبت می‌شود؛ برنامه کارهای وزنی، ظرفیت خط و محاسبه خودکار وجود ندارد.
- شماره و فایل قرارداد ثبت می‌شود؛ تنظیم خودکار متن قرارداد یا امضای حقوقی دیجیتال انجام نمی‌شود. تأیید داخلی با هویت و زمان ثبت می‌شود.
- اعلان داخل پنل از کارتابل ساخته می‌شود؛ outbox آماده است اما ارسال پیامک/ایمیل و worker زمان‌بندی‌شده هنوز متصل نشده است.
- MFA، بازیابی رمز، لغو نشست فوری، مدیریت جانشین، لغو/توقف مستقل سفارش و بازگشایی تحویل هنوز پیاده نشده‌اند.
- موتور گردش ثابت است؛ ویرایش بصری فرایند و مهاجرت نسخه فرایند وجود ندارد.
- تاریخ در لیست‌ها شمسی است؛ ورودی تاریخ از date picker استاندارد مرورگر استفاده می‌کند.
- این نسخه جایگزین نرم‌افزار حسابداری نیست؛ مقدار پول به تومان و به صورت عدد صحیح ذخیره می‌شود.

## انتشار

`.openai/hosting.json` فقط فرانت خروجی `out/` را منتشر می‌کند. کد API همراه منبع محفوظ است ولی میزبان استاتیک آن را اجرا نمی‌کند. برای انتشار فرانت متصل به API، آدرس عمومی امن API باید در زمان build تنظیم شود.
